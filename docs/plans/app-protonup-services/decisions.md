# YAN-822 orchestrator decisions

These decisions are binding for the plan and implementation of M1-32: moving the protonup, Proton migration and umu database services into `crosshook-app`. Paths are relative to `src/crosshook-native/`. Research lives in `research-*.md` in this directory.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Three service directories go under `crates/crosshook-app/src/services/`: `protonup/`, `proton_migration/` and `umu/`, following the community/steam shape: a `#[derive(Clone)]` struct, a positional `new()`, `async` public methods, `run_blocking` for store or filesystem work, `AppError` only, a `tests/` subdirectory, files under ~500 lines, `static_assertions::assert_impl_all!(…: Send, Sync)`. `Services` gains `protonup`, `proton_migration` and `umu` fields; three `.manage()` lines go in `src-tauri/src/lib.rs`, and the `ProtonInstallRegistry` `.manage` and type are deleted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D2  | **IPC contract frozen.** All 15 command names, the camelCase wire arg keys, the serde shapes, the `protonup:install:progress` event name and payload and the `bool` return of `protonup_cancel_install` stay the same. The pre-existing snake_case caller drift (`force_refresh`, `steam_client_install_path` in three TS callers) is **not** fixed here; it is filed as a follow-up. Tauri commands stay in `src-tauri` as thin delegates taking `State<Service>`. Each of the three command files gets a `command_names_match_expected_ipc_contract` pin test. Mocks and `check-mock-coverage.sh` stay green; no frontend changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| D3  | **Catalog identity is a pure function.** `verify_install_identity(request, supplied: Option<&ProtonUpAvailableVersion>, catalog: &[ProtonUpAvailableVersion]) -> Result<&ProtonUpAvailableVersion, IdentityError>`: find by `(provider, version)`; when `supplied` is `Some`, compare provider, version, `download_url`, `checksum_url` and `checksum_kind` with exact `Option<String>` equality (no URL normalization). Both install entry points call it (legacy sync passes `None`). The job installs the **catalog** entry, never the caller DTO. The three existing async `Err` texts are kept verbatim; the legacy missing-version result stays `Ok` with `DependencyMissing`.                                                                                                                                                                                                                                                                                                                                                                                                        |
| D4  | **Seams, no core HTTP changes.** App-private traits `ProtonCatalogSource` (default: core `list_available_versions_by_id`) and `ProtonInstaller` (default: core `install_version_with_progress`) and `UmuRefresher` (default: core `refresh_umu_database`), as boxed-future traits, plus a `#[cfg(test)]` constructor that injects fakes. Cache-hit tests may also seed `proton_release_catalog` via `MetadataStore::open_in_memory()`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| D5  | **Install as a JobRegistry job; one registry.** `start_install(owner, request, version)` verifies identity before allocating anything, then starts a `JobRegistry` job of kind `protonup-install` with `JobKey` `protonup-install:<provider>:<version>` (second concurrent install of the same version → `Conflict`, protecting the shared temp archive). The `JobId` string **is** the `op_id`. Progress keeps core's `ProgressEmitter`; `start_install` returns `{ op_id, progress: broadcast::Receiver }` and the Tauri adapter pumps it to `protonup:install:progress`. The pump continues on `RecvError::Lagged` and stops on `Closed`. If the installer returns `Err` (or a failed result) without having emitted a terminal phase, the service emits a synthetic `Phase::Failed` with a fixed, path-free message so the UI never hangs at "resolving".                                                                                                                                                                                                                               |
| D6  | **Owner-checked cancel.** `InstallOwner` is an opaque newtype derived by the adapter from the invoking Tauri webview label (an injected `tauri::Webview`/`WebviewWindow` param, never a JS arg). The service keeps `Arc<Mutex<HashMap<JobId, InstallOwner>>>`; entries are inserted before the job body can finish and removed when the job ends. `cancel_install(owner, op_id)` returns `Err(AppError NotFound "install operation was not found")` for both unknown and foreign op ids (no existence oracle) and never reaches `JobRegistry::cancel` for ids not in the map (so unrelated jobs cannot be cancelled). The adapter maps `NotFound` to `Ok(false)` to keep the IPC `bool`; own active → `Ok(true)`.                                                                                                                                                                                                                                                                                                                                                                           |
| D7  | **Uninstall root authority (security).** The caller-supplied `steam_client_install_path` must not mint an uninstall root. The service resolves trusted roots from the backend: the configured Steam path from settings (or `SteamService::default_client_install_path()`), and honours the caller's path only if it canonically equals one of the backend-discovered Steam roots (`discover_steam_root_candidates`); otherwise it is ignored. Core `plan_uninstall` stays the containment authority (canonical, direct child of a root, system denylist). The service additionally rejects any raw `Component::ParentDir` in `tool_path` and runs `crosshook_core::fs_util::ensure_within_workspace(root, tool_path)` against the matched root before core planning, so `..` and intermediate-symlink escapes fail closed. `uninstall` replans and rechecks; it never accepts a client plan. `resolve_install_roots` (listing only) keeps today's behaviour.                                                                                                                                |
| D8  | **Path-free errors.** Uninstall `error_message`, install failure messages forwarded in progress, umu refresh errors and all `AppError`s use fixed policy texts per error variant (e.g. "refusing to delete a system path", "path is not inside a known Proton install root", "Proton tool was not found", "failed to remove the Proton tool", "failed to refresh the umu database"). Underlying details are logged with `tracing` only. Structured path DTO fields (`installed_path`, `InstallRootCandidate.path`) remain.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D9  | **Offline.** If `settings.offline_mode` is on: `start_install` → `AppErrorKind::Unavailable` "offline mode is enabled" before any job; legacy `install_version` → `Ok` result with `success:false`, `error_kind: NetworkError` (or closest existing kind) and the same text; `list_available_versions` forces `force_refresh=false` and serves cache with its existing stale/offline markers (if core has a cache-only read, use it so no live fetch happens; otherwise keep current fallback and note it). umu refresh and coverage behaviour unchanged (no new gate); GAMEID lookup keeps its cache fallback.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D10 | **Migration service.** `ProtonMigrationService { profiles, writer, steam }`: `check` moves the A-4/A-5 logic from `src-tauri/src/commands/migration.rs` into `run_blocking`; `apply`/`apply_batch` delegate to `ProfileWriter` (already async). **Golden test first:** before refactoring, add `migrate` and `batch_migrate` scenarios to `crates/crosshook-app/tests/profile_writer_golden.rs` with fixtures captured from the unmodified code, then assert the service output is byte-identical.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D11 | **umu service.** `UmuService { metadata, refresher }`: `refresh`, `coverage(Option<String>)` (blank → `Unknown`, `run_blocking`), `clear_gameid_cache`. `bootstrap/scans.rs::schedule_umu` calls `services.umu.refresh()` instead of core directly; `CROSSHOOK_BENCH=1` skip stays.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| D12 | **Tests (critical only).** `services/protonup/tests/security.rs`: AC1 (missing version, provider mismatch, both entry points), AC2 (URL host, path, Some→None, query), AC3 (checksum URL host/path/None, checksum kind), authoritative entry used (caller `asset_size`/`release_url` ignored), each rejection asserts zero installer calls and `jobs.job_counts() == (0,0)`; AC4 foreign owner rejected and job not cancelled, unrelated JobRegistry job id rejected and untouched, own cancel works; AC5 with real temp dirs: `..` (ending outside and ending inside), final/intermediate symlink escape, sibling-prefix root, root itself, nested child, caller-supplied fake Steam root ignored, outside sentinels untouched, error text path-free. `tests/install.rs`: op_id returned before the job finishes, synthetic `Failed` on early error, Conflict on duplicate, offline Unavailable, owner map empty after completion. Migration golden (AC6). umu: fake refresher error is sanitized. Tests that need `HOME` use an env lock or a test seam; no `/tmp/crosshook-logs` writes. |
| D13 | **Filed as follow-ups, not in scope:** TS snake_case arg drift; redirect-hop allowlisting for Proton downloads; mid-extract cancellation; offline gate for umu refresh; manual Proton-GE install/cancel from the test plan; `openat2` race-free deletion.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
