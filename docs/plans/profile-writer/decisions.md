# YAN-811 orchestrator decisions

Binding for the plan and implementation. Each favours data integrity, security, UX and stability.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | `profiles-changed` payload is `{ "reason": { "kind": "<snake_case>", ...variant fields }, "names": [..] }`. `ProfileChangeReason` uses `#[serde(tag = "kind", rename_all = "snake_case")]`. Rename: `names: [new]`, `reason.from: old`. Delete: `names: [removed]`. Duplicate: `names: [copy]`. `names: []` means only "conservative resync" (bus lag). No legacy string form or dual emission.                                                                                                                                             | Maps the Rust enum directly; a discriminated union in TS; one producer avoids racing refreshes.                                                                                                              |
| D2  | Public API = typed async facade methods on `ProfileWriter` (save, delete, duplicate, rename, set_favorite, section saves, presets, history/diff/rollback/known-good, import/export, list/load/summaries, ProtonDB accept, migration apply). Every facade funnels mutations through one private `commit` pipeline (validate → load → mutate → persist once → observe → revision → health invalidate → publish). The facade picks the reason; callers cannot mislabel provenance.                                                             | Satisfies "built around one commit pipeline" without a caller-defined reason/mutation mismatch surface.                                                                                                      |
| D3  | **Write serialization:** `ProfileWriter` holds an `Arc<std::sync::Mutex<()>>`. Every mutating closure takes it inside `run_blocking` (recovering from poison via `into_inner`). Reads do not take it.                                                                                                                                                                                                                                                                                                                                       | Today sync Tauri commands run serialized on the main thread. Moving them to the blocking pool would let an autosave interleave with a full save and lose updates. The lock keeps the old ordering guarantee. |
| D4  | The event is published inside the blocking closure after the primary persistence succeeds, even if advisory metadata effects fail. No event for validation or save failures, a no-op rename, or migration `AlreadyValid`/`Failed`.                                                                                                                                                                                                                                                                                                          | A dropped command future can't lose the notification for a write that persisted.                                                                                                                             |
| D5  | Health "invalidate" = a new parameterized core `MetadataStore::invalidate_health_snapshot(profile_id)` (DELETE of the cached row, no schema change), fail-soft. No validation runs inside commit. Favorite skips TOML, revision and health entirely.                                                                                                                                                                                                                                                                                        | Matches the issue pipeline; keeps commit cheap; the frontend revalidates on non-favorite reasons.                                                                                                            |
| D6  | Degraded metadata: a TOML save succeeds; observe, revision and health steps are skipped with `tracing::warn!`. The service returns typed `warnings` inside its commit result so the native UI can show them. Classic surfaces the state through the existing `MetadataStatusBanner` (`useMetadataStoreStatus`); a test asserts it renders when metadata is unavailable. IPC return shapes are unchanged. Metadata-required operations (history, diff, rollback, known-good, bundled preset, favorite) return explicit `Unavailable` errors. | Meets "logged and surfaced" without breaking IPC contracts.                                                                                                                                                  |
| D7  | Collection composition (`apply_collection_defaults`, the collection branch of summaries) stays in `src-tauri` for M1-35. `profile_load` calls `ProfileWriter::load`, then the shell helper.                                                                                                                                                                                                                                                                                                                                                 | The issue explicitly excludes collections.                                                                                                                                                                   |
| D8  | Core domain mutation rules are extracted (not duplicated) so that commit writes once: `GameProfile::apply_launch_optimizations`, `apply_command_arguments`, `materialize_launch_optimization_preset`, `apply_manual_optimization_preset`, `ProfileStore::unique_copy_name`, `ProfileStore::save_without_companion`, `profile::migration::prepare_profile_migration`. The existing store methods delegate to them.                                                                                                                           | One implementation per rule; migration keeps its no-MangoHud-companion policy.                                                                                                                               |
| D9  | Revision snapshot keeps today's serialization (`toml::to_string_pretty(&profile)` then `sha256_hex`) and the retention fallback; rollback verifies through `verify_config_revision` (SHA plus HMAC) before any write. Duplicate and rename now capture revisions and emit events (new, issue-mandated).                                                                                                                                                                                                                                     | Byte-compatibility of existing revision hashes; integrity first.                                                                                                                                             |
| D10 | Lutris: `ProfileWriter::record_imports(Vec<ImportedProfileWrite>)` runs the shared post-persistence effects with reason `Imported`. Community import is unchanged (it doesn't use the moved helpers).                                                                                                                                                                                                                                                                                                                                       | Required to delete the Tauri helpers; no import redesign.                                                                                                                                                    |
| D11 | Errors: reuse `AppError`/`AppErrorKind`; Tauri maps `error.to_string()`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Existing sanitization; no new error type.                                                                                                                                                                    |
| D12 | Security hardening inside the moved code only: `profile_export_toml` validates the profile name (`validate_name`) before interpolating it into the TOML header. Other security research findings (legacy-import app-id validation, env reserved-key symmetry, slug collisions, art-import source confinement) become Linear follow-ups.                                                                                                                                                                                                     | Keeps the refactor behaviour-preserving while closing a header-injection risk in code we touch.                                                                                                              |
| D13 | Frontend: a shared `src/types/profile-events.ts` and `src/lib/profileEvents.ts` (`parseProfilesChanged(unknown)`: a malformed payload counts as a resync; `profileChangeAffectsHealth(reason)` is false only for `favorite_toggled`). The five listeners are updated. The health dashboard's favorite star and ordering update from `ProfileContext.favoriteProfiles` without a rescan. Mocks emit through one typed helper.                                                                                                                | Zero `batch_validate_profiles` on favorite, with no stale favorite display.                                                                                                                                  |
| D14 | Bridge: `startup_bridge.rs` gains a `ProfilesChanged` arm (emitting the object payload). On `Resync` it also emits `{reason:{kind:"saved"},names:[]}`.                                                                                                                                                                                                                                                                                                                                                                                      | Single bus receiver; a lagging receiver never leaves views stale.                                                                                                                                            |
| D15 | Golden fixtures are captured from the **pre-refactor** code (save, rename, duplicate, rollback) before the writer changes, stored under `crates/crosshook-app/tests/fixtures/profile_writer/`, and compared byte-for-byte.                                                                                                                                                                                                                                                                                                                  | Proves byte compatibility.                                                                                                                                                                                   |
