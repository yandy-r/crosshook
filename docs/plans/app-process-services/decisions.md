# YAN-815 / YAN-1538 orchestrator decisions

These decisions are binding for the plan and implementation of M1-31 (move install, update, run-executable and prefix-deps services into `crosshook-app` with process supervision) and YAN-1538 (lifecycle-bound `check_installed` probe). Paths are relative to `src/crosshook-native/`. Research lives in `research-*.md` in this directory.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | **Layout.** Four service directories under `crates/crosshook-app/src/services/`: `install/`, `update/`, `run_executable/`, `prefix_deps/`, following the protonup/community shape: `#[derive(Clone)]` struct, positional `new()`, `#[cfg(test)] with_seams()`, `async` public methods, `run_blocking` for store/filesystem work, `AppError` only, `tests/` subdirectory, files ≤ ~500 lines, `static_assertions::assert_impl_all!(…: Send, Sync)`. `Services` gains the four fields; `src-tauri/src/lib.rs` `.manage()`s them and drops `InstallState`/`UpdateProcessState`/`RunExecutableProcessState`/`PrefixDepsInstallLock`.                                                                                                                                                                                                                                                                                                                                                                                                          |
| D2  | **IPC contract.** All 16 command names, camelCase arg keys and event names stay. Changes are additive only: results and event payloads may gain an id field (`run_id`/`op_id` = `JobId` string). `RunCommandError` (tagged `kind`, `field`) keeps its exact wire shape. Each command file gets a `command_names_match_expected_ipc_contract` pin test. Tauri commands stay thin `#[tauri::command]` delegates in `src-tauri` (mock-coverage gate scans only `src-tauri`/core). `update-log` payload shape is unchanged (ConsoleView consumes it). Raw request `prefix_path` is echoed in prefix-deps events (listeners match by exact string).                                                                                                                                                                                                                                                                                                                                                                                            |
| D3  | **App owns spawning.** Core stops spawning/awaiting long-running children for these flows: core exposes builders that return a prepared `tokio::process::Command` (plus any post-processing fns made `pub`), and the app spawns and supervises. `install_game`'s inner `block_on` wait is removed. Proton-based builders get a lifecycle-bound variant (`--watch-bus` after `--host` under Flatpak) with `process_group(0)` and `kill_on_drop(true)`. All host spawns in scope go through `crosshook_core::platform` lifecycle builders. Behaviour change (accepted, stated in PR): quitting CrossHook now ends a running installer/updater/ad-hoc executable/winetricks on the host instead of orphaning it.                                                                                                                                                                                                                                                                                                                             |
| D4  | **Supervision.** Every long-running flow is a `JobRegistry` job. Cancel = SIGTERM to the job's process group, escalating to SIGKILL after the existing grace period (`supervise_child`). Stop = immediate SIGKILL to the process group; add a second "stop/kill-now" signal to `supervise_child` (app-internal API). **Never** signal a stored numeric PID and never run host `kill <pid>`; delete that code. Pipes are drained with bounded, lossy (invalid UTF-8 tolerant), cancel-aware drains (reuse `services/launch/streaming.rs` pattern); completion is published only after the final log drain.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D5  | **Per-prefix exclusivity.** One shared key `JobKey("prefix:<normalized canonical prefix path>")` is held by prefix-deps install, repair, startup recovery, install-game, update and run-executable (resolved prefix, including throwaway `_run-adhoc/*`). A second job on the same prefix → `AppErrorKind::Conflict` (existing user-visible message kept where one exists). Different prefixes run in parallel (replaces the global `PrefixDepsInstallLock`; accepted behaviour change). Ad-hoc throwaway prefixes get a unique per-run directory suffix so same-stem runs can't collide, and the key is held through cleanup. `check_prefix_dependencies` does **not** take the key (today it doesn't; no regression).                                                                                                                                                                                                                                                                                                                   |
| D6  | **Cancel ownership.** Cancel/stop commands keep their current no-argument signature. The service tracks its own active `JobId` per flow plus an owner derived from the invoking webview label (as protonup D6); a foreign owner or no active job → `Ok(false)`/no-op, never touches unrelated jobs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| D7  | **`PrefixVersionJournal`.** App type over two seams (`JournalStore` → `MetadataStore`, `PrefixVersionRestorer` → core restore) with: `status`, `record` (returns `#[must_use] JournalTicket`), `resolve`, pure `decide()`, `recover_before_install`, `recover_on_startup`. Storage and format unchanged (`prefix_version_restore_journal`); add one read-only `list_prefix_version_restores()` to the metadata store (no schema change). Invariants I1–I14 from `research-journal.md` are binding: pending row written before install starts; row deleted only after a restore verified against `system.reg`; delete failure after a verified restore marks the row `failed` (fixes install-path bug); always normalized `pfx` keys; install→restore→persist under one prefix hold; restore always runs after the install child exits, **including after user cancel**; restore uses the recorded tool. Before replay, `binary_path` is re-validated (absolute, exists, regular executable file); invalid → mark `failed`, never execute. |
| D8  | **Recovery triggers.** Startup: a background job in `bootstrap/scans.rs` (lightweight option; `CROSSHOOK_BENCH=1` skip like other scans) lists rows, retries only `pending` rows, skips when the metadata store is unavailable, holds each prefix key, and skips (leaves `pending`) a prefix that has a live process using it. `failed` rows wait for explicit Repair. Before each install: `recover_before_install` attempts the same recovery for that prefix under the already-held key; unresolved → existing refusal error.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D9  | **Panel visibility.** `PrefixVersionRepairStatus` gains additive runtime-only fields: `in_progress: bool` (prefix key held → panel does not show "repair required" mid-install) and `last_recovery: Option<{outcome: restored\|failed, message}>` set by startup/pre-install recovery for that prefix. `PrefixDepsPanel` shows a non-blocking note for `restored` and the existing blocking alert for `failed`. TS types and mocks updated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| D10 | **Run executable UI.** Panel subscribes once on mount to `run-executable-log` (`{run_id, line}`) and `run-executable-complete` (gains `run_id`), filtered by the `run_id` returned from `run_executable`; shows live lines in a `role="log"` region, text only (no HTML), capped buffer. Remove `NO_EXIT_RECEIVED`, `exitHolder`, `invokeResolved` and the `completedBeforeInvoke` flag in `useUpdateGame.ts`; after invoke use a functional state update so an already-final stage is kept. Mocks for `run_executable`/`update_game`/`install_prefix_dependency` emit log lines and completion. Panel copy saying output goes to the runtime console is corrected.                                                                                                                                                                                                                                                                                                                                                                       |
| D11 | **Logs.** Files stay in `/tmp/crosshook-logs` via `jobs::create_log_path_in` (injectable dir for tests). The child's stdio is attached to the handle returned by `create_new` (no reopen by path; fixes symlink-follow). Tail via `log_tail::follow`. Delete `src-tauri/src/commands/log_stream.rs`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| D12 | **Offline.** `offline_mode` on → `install_prefix_dependency` returns `AppErrorKind::Unavailable` "offline mode is enabled" before any job (winetricks downloads). Install-game, update, run-executable, check and repair are local and ungated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D13 | **Tool selection.** One pure `resolve_tool(settings_override, detected, steam_app_id)` replaces the duplicated check/install selection: protontricks requires a valid Steam App ID (non-empty, ASCII digits, fits `u32`, non-zero — current behaviour kept); otherwise fall back to winetricks. YAN-1538: `check_installed` uses `host_command_with_env_and_directory_lifecycle`; a test asserts the Flatpak argv has `--watch-bus` right after `--host`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D14 | **Tests (critical only).** `prefix_deps/tests/journal.rs`: J1 crash after version change before restore → startup restore + row deleted; J2 crash after restore before delete → verified state, row deleted; J3 restore fails → row `failed`, error recorded, not deleted; J4 delete decisions (delete failure after verified restore → `failed`; startup skips `failed`; invalid `binary_path` → `failed`, restorer not called; live prefix → left `pending`). `tests/tools.rs`: fallback matrix + App ID validation (empty, non-digit, overflow, zero, valid). `tests/exclusivity.rs`: second install same prefix (incl. symlink alias) → `Conflict`; different prefix allowed. `tests/cancel.rs`: cancel still runs restore. Run-executable: unique throwaway dir per run; foreign-owner cancel no-op. Frontend: vitest for `useRunExecutable` (log lines rendered; completion-before-invoke-resolves keeps final stage). Security tests must be falsifiable (fakes honour arguments).                                                 |
| D15 | **Out of scope → follow-ups:** native env clearing (L2); gateway lint for `Command::new(<variable>)` (L6); splitting `core/prefix_deps/runner.rs` (1180 lines); narrowing `kill_processes_using_prefix` scope (M2, behaviour kept as today); manual test plan (prefix-dep install, kill-and-restart recovery, run-and-cancel executable, Flatpak).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
