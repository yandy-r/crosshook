| D1  | `UiSettings` lives in a new `crates/crosshook-core/src/settings/ui.rs` and is the `ui` field of `AppSettingsData` (`[ui]` table). Keys follow the issue spec, not the migration README: `library_view_mode` (`grid`/`list`, `Option`, absent = not set, read as `grid`), `window_width` / `window_height` (`Option<u32>`, absent = centred default; width clamped 800..=16384, height 600..=16384), `ui_scale` (`f64`, 0.75..=2.0, default 1.0), `density` (`compact`/`comfortable`/`spacious`, default `comfortable`), `renderer` (`auto`/`wgpu`/`gl`/`tiny-skia`, default `auto`; `tiny-skia` is an explicit serde rename), `controller_mode` (`auto`/`on`/`off`, default `auto`), `sidebar_collapsed` (bool, default `false`), `inspector_width` (240..=640, default 320), `console_drawer_height` (120..=800, default 280), `palette_recent` (list of command ids, MRU first, at most 20, de-duplicated keeping the first occurrence). `None` options are not serialized. | The issue is the spec. Defaults for density and the two panel sizes are unspecified; these match Classic. `f64` keeps save→reload byte-identical.                                                                                                                                                    |
| D2  | `[ui]` parsing is lenient and never fails the settings load. `UiSettings` has a hand-written `Deserialize` that reads a `toml::Value`: a non-table `ui` resets to defaults; each known key that has the wrong type or an invalid value is reset to its default, and out-of-range numbers are clamped (non-finite `ui_scale` resets to 1.0; integers are read as `i64` before clamping). Each fix-up logs one `tracing::warn!` naming the key and a fixed reason, never the value. Unknown `[ui]` keys are kept in `ui.extra` (wired into `clear_extra` / `preserve_extra_from`). Keys outside `[ui]` keep today's strict behaviour.                                                                                                                                                                                                                                                                                                                                           | The spec requires clamp/reset with a warning. Today one bad enum fails the whole file and the app falls back to full defaults (research-business). Warnings emitted before logging is up are re-emitted on the next `SettingsService::load` (Classic loads settings at mount), so no extra plumbing. |
| D3  | `palette_recent` ids must match `^[a-z][a-z0-9-]{0,31}(:[a-z0-9][a-z0-9-]{0,31}){0,2}$` (at most 98 bytes). Invalid entries are dropped with a warning that gives only the count.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Ids, never paths: `settings.toml` is copied into diagnostic bundles, so no profile names or paths may be stored (research-security). The native palette (M4-10) owns its id set.                                                                                                                     |
| D4  | Classic never writes `[ui]` through `settings_save`. `SettingsSaveRequest` is unchanged and `merge_save_request` copies `ui` from the stored settings. `settings_load` returns `ui` (without `extra`), taken from the in-memory `UiSettingsService` snapshot so a pending throttled write is never shadowed by the older on-disk value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Classic sends full snapshots; carrying `ui` would let stale snapshots overwrite newer values (lost update).                                                                                                                                                                                          |
| D5  | `crosshook-app` gets a `UiSettingsService` (in `services/settings/ui.rs`, writer in `services/settings/ui_writer.rs`), exposed from `Services`. It holds the current `UiSettings` in memory, loaded at construction. Typed getter `get()` and typed setters (`set_library_view_mode`, `set_window_size`, `set_ui_scale`, `set_density`, `set_renderer`, `set_controller_mode`, `set_sidebar_collapsed`, `set_inspector_width`, `set_console_drawer_height`, `push_palette_recent`) clamp, update memory immediately and mark the key dirty. A background throttle persists at most once per second: a leading write when idle, then one trailing write for changes made inside the window. A write applies only the dirty keys onto the on-disk `[ui]` through `SettingsStore::update` (atomic save, unknown keys preserved). `flush().await` writes pending keys at once; shells call it on shutdown.                                                                        | Spec: debounced to at most 1 write/s; 100 resize events ⇒ at most 2 writes. Dirty-key patches avoid clobbering other keys or other writers. No generic debounce utility (KISS).                                                                                                                      |
| D6  | Write failure: in-memory values keep applying for the session. The first failure in a session publishes `AppEvent::UiSettingsPersistFailed` (new variant on the `#[non_exhaustive]` enum) and logs an error; later failures only log. Classic does not render a toast for it in this PR (Classic has no global toast service and is silent for all settings save errors today); the native UI consumes the event when its shell exists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Spec: "single error toast". The producer side is built and tested here; the consumer lands with the native shell (M1-19).                                                                                                                                                                            |
| D7  | One-time import: `crates/crosshook-core/src/settings/webkit_import.rs` reads `library_view_mode` from Classic's WebKit localStorage (`<data_local_dir>/dev.crosshook.CrossHook/localstorage/tauri_localhost_0.localstorage`, path built only from `platform::base_dirs()` and the existing app-id constant). Hardened read: regular file only (no symlink, no FIFO), at most 16 MiB, opened as `file:…?mode=ro&immutable=1` with `READ_ONLY                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | URI                                                                                                                                                                                                                                                                                                  | NOFOLLOW | NO_MUTEX`, `trusted_schema`off,`ItemTable`must be a real table, value must decode (UTF-16LE) to exactly`grid`or`list`. Every failure returns `None`silently (debug-level log with a fixed reason). The app layer runs the import during bootstrap after settings load, only when`ui.library_view_mode`is`None`, and persists only a successful result (via `SettingsStore::update`, re-checking it is still `None`). A missing file writes nothing. The import reads from the validated descriptor into a bounded copy in a private temporary directory so SQLite never opens the user's path, and diagnostic bundles exclude recent-palette identifiers. | Spec: best-effort, read-only, never an error dialog. Most users have no file (research-import). Not writing on a miss avoids touching `settings.toml` at every first start; once the key exists the file is never read again. |
| D8  | Classic: new Tauri command `settings_set_library_view_mode(mode)` delegating to `UiSettingsService::set_library_view_mode`; matching browser-dev mock handler (replaces the nested `ui` object). `PreferencesContext` exposes `libraryViewMode` and `setLibraryViewMode` (optimistic state update, no reload). `LibraryPage` stops using `localStorage`; dead `localStorage` stubs in tests are removed; the `routes.a11y` fixture gets `ui`. Tauri calls `flush()` on app exit. While settings load, Library renders `grid` (brief flash accepted).                                                                                                                                                                                                                                                                                                                                                                                                                          | Narrow command avoids the full-snapshot race (research-classic).                                                                                                                                                                                                                                     |
| D9  | "Visible in native and vice versa": no native UI crate exists yet (M1-13). The criterion is proven at the shared-service layer: a write through the Classic command path is read by a fresh `UiSettingsService` (what native will construct) and the reverse; plus a Vitest case where `settings_load` returning `ui.library_view_mode = "list"` renders list view. Live cross-process propagation is out of scope (single-instance lock is M1-12).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Honest scope: the shared contract is what both UIs use.                                                                                                                                                                                                                                              |
| D10 | The hand-written `AppSettingsData` `Debug` gains `ui`; `UiSettings` has a hand-written `Debug` that prints known keys, `palette_recent` as a count, and `extra` as a key count.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | No leaking of unknown keys; matches existing redaction.                                                                                                                                                                                                                                              |
