# Feature Spec: storage, mods, collections, launcher-export, version and Steam services in `crosshook-app`

Tracking: Linear YAN-847 / GitHub #539 (M1-35). Target `crosshook v0.7.0-alpha.1`, trunk-only off `main`, worktree `crosshook-yan-847`. Paths are relative to `src/crosshook-native/`. Binding decisions D1–D16: [decisions.md](./decisions.md). Frozen Rust contracts: [b0-contracts.md](./b0-contracts.md). Batched plan: [app-storage-services.plan.md](./app-storage-services.plan.md).

## Problem

45 Tauri commands across seven `src-tauri/src/commands/` files hold application orchestration that the future native UI and CLI cannot reach: storage scan/cleanup with its only-in-the-shell allow-list, mods registry + detection, collections CRUD/defaults/TOML exchange, launcher export (576 lines in `export.rs`), version tracking, Steam/Proton discovery and game metadata/art. 33 of the 45 are synchronous `fn`s that run SQLite and filesystem work on the IPC caller thread (`export_launchers`, `list_proton_installs`, all collections, all version, both art imports). The storage-cleanup allow-list — the security boundary that keeps a renderer from deleting arbitrary paths — has **zero tests** (research-business §8.3). `apply_collection_defaults` is still stranded in `commands/profile/shared.rs` (profile-writer D7 deferred it here). Launcher output has no golden tests. A disabled metadata DB silently no-ops collections writes (`collection_create` returns `Ok("")`).

## Scope

Move all of it into six service directories under `crates/crosshook-app/src/services/` (D1): `storage/`, `mods/`, `collections/`, `launcher_export/`, `version/`, `steam/` (game metadata and art fold into `steam/`). Every service follows the profiles/launch shape: `#[derive(Clone)]` struct, positional `new()`, `async` public methods doing blocking work inside one `run_blocking` closure per operation, `AppError` only, `tests/` subdirectory, files under ~500 lines. The Tauri commands become thin delegates with byte-identical IPC names, argument keys, serde field names and return shapes (D12). `apply_collection_defaults` moves to `CollectionsService::apply_defaults` (D9). Storage scan becomes an exclusive `JobRegistry` job (D3).

## Non-goals

- No SQLite schema change, no TOML format change, no image-cache/media path change, no new events (D12), no `AppEvent` variants.
- Collections TOML import stays a preview; the frontend keeps orchestrating the apply step (D16). Mods add/remove stay metadata-only.
- No fix for `rename_launcher` resetting umu/runtime fields, the settings-failure inconsistency between `check_launcher_for_profile` and stale/slug matching, the duplicated appmanifest lookup (5th copy moves as-is), SteamGridDB initial-URL validation, handle-pinned deletion for the ancestor-swap race, `offline_mode` consultation for art fetch — all filed as follow-ups (D15).
- No host-tool spawning in services; only core calls (`check-host-gateway.sh`). No trait seams for stores/filesystem; tests use tempdir stores + `MetadataStore::open_in_memory()`/`disabled()`.
- CLI adoption of these services (separate issue). The manual prefix-cleanup test from the issue's test plan stays manual (D15).

## Architecture

### Wiring (D2)

`Services::new(&Stores, EventBus, Handle, JobRegistry)` gains the app's job registry: `app_bootstrap.rs:116` becomes `Services::new(&stores, app.events().clone(), app.runtime_handle(), app.jobs().clone())` (`App` exists before `Services` there — verified `app` is built at :94). The only other caller is `bootstrap/stores/tests.rs:127-131`, which passes `JobRegistry::default()`. `Services` gains six fields (`storage`, `mods`, `collections`, `launcher_export`, `version`, `steam`); `src-tauri/src/lib.rs` gains six `.manage(services.<x>.clone())` lines after line 49. No `JobRegistry::default()` ambient fallback in production wiring. Scan jobs are therefore cancelled on app shutdown through the registry's parent token.

### Scan as a job (D3)

`StorageService::start_scan()` starts the scan inside `JobRegistry::start` with the exclusive `JobKey` `"prefix-storage-scan"` (a concurrent request gets `Conflict`) and reports progress through `JobContext::progress`. Because `Outcome` carries no payload, the result goes into a service-owned slot keyed by `JobId`, read with `scan_result(&JobId)` (take semantics). `scan()` is the awaitable convenience: start, await `Finished` on the handle, take the result. The Tauri command `scan_prefix_storage` awaits `scan()`, so its IPC result is unchanged. Cleanup stays a direct call, never a job.

### Error and IPC contract

Services return `AppError` only. The adapters map once to today's exact strings (D7/D8/D12): mods `Unavailable` → `metadata_unavailable: the metadata database could not be opened`; detect's missing game path → `Validation { field: "game_path" }` → `no_game_path: set the game executable path to enable detection`; `list_profile_mods` keeps `{available:false, mods:[]}`; storage history keeps `available:false` + empty lists; `fetch_game_cover_art` keeps `Option<String>` with the adapter mapping service `Unavailable` → `Ok(None)` while cached art still returns `Some(path)`. `MetadataStoreError::Validation(msg)` from the collections/mods stores keeps `msg` through the crate-private D8 helper (`AppErrorKind::Validation { field: "collection" | "mod" }`, passed through `sanitize_message`), so "a mod named … is already registered", "mod not found", "profile not found when adding to collection: X" and "collection not found" stay user-visible. All other variants use the existing `From<MetadataStoreError>`.

### DTO placement (D13)

`PrefixStorageHistoryResponse`, `ProfileModsResponse`, `VersionCheckResult`, `VersionSnapshotInfo` and the `LauncherRenameRequest` struct live in the services with serde names unchanged (they move from `commands/storage.rs:147-152`, `commands/mods.rs:50-54`, `commands/version.rs:21-42`). ## Data and persistence boundary

Unchanged. SQLite: `prefix_storage_snapshots` / `prefix_storage_cleanup_audit`, `profile_mods` (v26), collections tables, `version_snapshots`, `external_cache_entries`, `game_image_cache`, launcher observations — written by the same calls under the same conditions; `check-schema-version.sh` stays green. Profile TOML unchanged. Image cache stays `$LOCALDATA/crosshook/cache/images`; imported art stays `$LOCALDATA/crosshook/media/{covers,portraits,backgrounds}`. Scans, job state, result slots and stale flags are runtime-only. No migration. Offline: art fetch reports `Unavailable` at the service level while cached art is still returned; metadata lookup keeps its `state: "unavailable"` data shape. DB disabled: collections and mods writes return `Unavailable` before any write (D7); scan/cleanup and detection keep working.

## Security contract

- **D4 — cleanup authorization.** `StorageService::cleanup` is the single orchestrator. In one blocking closure: reload profile references; run a fresh scan; accept only exact `(kind, resolved_prefix_path, target_path)` tuples from that scan, deduplicated; pass the **server-produced** target onward, never the caller's object. Trusted roots come from profile inventory, never from the request. Today's allow-list (`commands/storage.rs:64-86`) is preserved and becomes the tested boundary.
- **D5 — no-follow and containment in core.** `crosshook-core/src/storage/prefix_health/cleanup.rs` gains, before canonicalization: `symlink_metadata` checks on the target and the fixed intermediates below the prefix (`drive_c`, `drive_c/CrossHook`, `StagedTrainers`); rejection of symlinks, dangling links and non-directories; staged targets must be immediate children of the staged root; orphan and staged targets must be strict descendants, never equal to their roots; canonicalization failure fails closed. Rejections become `skipped` entries with fixed reasons. A residual ancestor-swap race between check and delete is documented, not claimed fixed (D15 follow-up).
- **D6 — rejected requests are reported.** A tuple missing from the fresh scan appears in the existing `skipped` list with reason `not present in a fresh storage scan` and gets a `skipped` audit row (fail-soft). Accepted deletions keep per-target `deleted` rows plus the `summary` row. `PrefixCleanupResult` shape unchanged.
- **D14 — hardening in moved code only.** `rename_launcher` validates and sanitizes the **old** slug the same way delete-by-slug does, and requires old and new paths to stay inside the resolved launcher directories. Custom-art import keeps magic-byte + 5 MiB validation and gains a bounded read that stops reading once the limit is passed (core `game_images/import.rs`).
- **Preserved as-is:** watermark + symlink checks on launcher delete/rename, HTTPS redirect host allow-list, API key never logged (`skip`/`skip_all` on spans), preview-only collection import (D16), mods add/remove never touching the filesystem, `is_in_managed_media_dir` never used as an authorization primitive.
