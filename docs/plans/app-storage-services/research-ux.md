# Research: UX / frontend contract surface (YAN-847 / M1-35)

Paths relative to `src/crosshook-native/`. Read-only research. All 45 commands in scope:
storage 3, mods 6, collections 13, export 12, version 4, steam 3, game_metadata 4 (steam + game_metadata `import_custom_cover_art`/`import_custom_art` counted in game_metadata).

## 0. TL;DR - what must not change

1. **Command names and arg keys (camelCase from Tauri; snake_case only _inside_ struct payloads).** The frontend calls `callCommand(name, args)` (`src/lib/ipc.ts:7`) which routes to `invoke` in Tauri or to `src/lib/mocks/*` in webdev. Renaming any command/arg breaks both.
2. **Serialized return shapes** (serde field names, snake_case) - see table in section 2.
3. **Error-string contract** (plain `String` rejections - frontend does `instanceof Error ? message : String(e)`; no structured error object is read anywhere):
   - `metadata_unavailable: ...` prefix (mods): `src/hooks/useProfileMods.ts:8` `METADATA_UNAVAILABLE_PREFIX`; `startsWith` checks at :86, :119, :136, etc. Triggers `unavailable` mode in HeroModsSection.
   - `no_game_path: ...` prefix (detect): `useProfileMods.ts:9`, stripped (`slice(prefix.length).trim()`) before display at ~:302.
   - `profile has no metadata record yet - save the profile once, then retry` (mods resolve_profile; displayed verbatim).
   - mod duplicate-name text `metadata validation error: a mod named “X” is already registered for this profile` / `metadata validation error: mod not found` (mirrored by mock `mods.ts` lines ~178/197).
   - `Unknown image type: {x}` / `Unknown art type: {x}` (game_metadata) - mocks mirror `unknown art type`.
   - Version: `profile '{name}' is not registered in the metadata store`.
   - Collections: `collection_id must not be empty`, `output_path must not be empty`, `path must not be empty`; duplicate-name text is surfaced from MetadataStore error `.to_string()` - UI shows it verbatim (CollectionsContext.tsx:236 etc.).
   - Reexport: `No profile found for launcher slug '{slug}'`.
   - Everything else: `error.to_string()` of core errors, shown verbatim (red text). **A new `AppError` -> String mapping in Tauri wrappers must keep `Display` text identical** and keep the prefix strings (`metadata_unavailable:` / `no_game_path:`) when mods service returns `Unavailable`. Note `crates/crosshook-app/src/error.rs` has no such prefix today (grep clean) - the Tauri mods wrapper (or service error Display) must produce `metadata_unavailable: the metadata database could not be opened` for the `available:false`-less paths.
4. **`ProfileModsResponse.available:false` path**: `list_profile_mods` returns `Ok({available:false, mods:[]})` when DB disabled (not an error). Spec "collections and mods report Unavailable" must map to this for mods; for mutations it is the `metadata_unavailable:` error string. HeroModsSection test locks `available:false` (`src/components/library/__tests__/HeroModsSection.test.tsx:109`).
5. **`get_prefix_storage_history` returns `{available, snapshots, audit}`** and `available:false` drives the banner "Scan history is unavailable (metadata database offline). Scanning and cleanup still work normally." (`components/settings/PrefixStorageHealthSection.tsx:300-302`). So scan + cleanup must keep working with DB disabled (audit rows fail-soft today). **DB-disabled collections: no partial writes** is new; frontend `applyImportedCollection` (CollectionsContext.tsx:233-290) already rolls back with `collection_delete`.
6. **No command in scope emits a Tauri event today** (grep of `emit(` in the 7 files: none). Frontend never `listen`s for storage/mods/collections/launcher/version/steam/metadata events. Adding a scan-job event is net-new UX; keeping the `scan_prefix_storage` request/response shape is mandatory (hook awaits the result, `usePrefixStorageManagement.ts:68`).
   Related events the frontend consumes that are NOT emitted by these commands: `profiles-changed` (startup_bridge.rs:39; useProfile.ts:227, useLibrarySummaries.ts:67, useProfileHealth.ts:285, useCommunityProfiles.ts:436), `version-scan-complete` (startup_bridge.rs:94; useProfileHealth.ts:296), `startup-job-finished`, `launch-complete`. The **browser mock** `check_version_status` fakes `version-scan-complete` after 300 ms (`lib/mocks/handlers/health.ts:232-244`), real command does not emit it.

## 2. Async-vs-sync UX implications

- **`list_proton_installs`** (currently a sync `fn`, steam.rs:35). Frontend already treats it as async (`await callCommand`). Making it `async` + `spawn_blocking`/`run_blocking` is invisible to callers. UX caveats to preserve:
  - `useProtonInstalls` has NO loading flag; shows `installs=[]` until resolved, `error` string on failure; guarded by `active` flag (stale response drop). `useProfilesPageProton.reloadProtonInstalls` (:35) has no stale guard, awaited by the caller after a ProtonUp install; an async scan must still resolve with the _post-install_ list (do not cache scans across calls).
  - Arg `steamClientInstallPath` is sent as `undefined` (omitted) when blank -> Rust `Option<String>` None -> falls back to `default_steam_client_install_path()`. Keep `Option<String>` semantic; empty-string `Some("")` must NOT be treated as None differently from today (today `Some("")` is passed straight to `discover_steam_root_candidates`).
  - Never emits events; "async scan" per spec = non-blocking command, NOT a job with events, unless a hook is added. Return the bare array (`Vec<ProtonInstall>` JSON), not a job handle.
  - Tests: `src/components/library/__tests__/useProfilesPageProton.test.tsx:48,82`, `HeroDetailProfilesTab.test.tsx:319,488` assert the exact call `('list_proton_installs', {steamClientInstallPath: ...})`.
- **`export_launchers`** (currently sync `fn`, export.rs:195, writes files + `observe_launcher_exported`). `useLauncherExport.exportLauncher` sets `isExporting` for the whole `validate_launcher_export` + `export_launchers` sequence and disables UI; already async-safe. After success it calls `refreshLauncherStatus()` (-> `check_launcher_exists`) fire-and-forget, so the metadata observe + file writes must be complete before the command resolves (do NOT return before files exist). The silent auto re-export (`pendingReExport` effect, useLauncherExport.ts:113-135, 150 ms timer) swallows errors. Returning an identical `SteamExternalLauncherExportResult` is the only requirement; no event needed.
- `scan_prefix_storage` is already `async` + `spawn_blocking`, UI shows `Scanning...` for the full duration; "scan as a job" must still resolve the original IPC call with the result (hook sets `scanSource='live'` from the resolved value). If a job id is introduced, the Tauri command must still await completion or the hook + mock must change together. Same for `cleanup_prefix_storage` (button `Cleaning...`; result must include `deleted`/`skipped`/`reclaimed_bytes` immediately so the outcome line can render before the follow-up rescan at PrefixStorageHealthSection.tsx:280-283).
- Other sync commands (all collections, version, mods preview/list for launchers, `check_launcher_*`) are awaited by hooks; becoming async is transparent.
- `fetch_game_metadata` is debounced client-side and request-id guarded - the service must be callable concurrently; duplicates are tolerated.

## 4. Browser-dev mock contract that must stay identical

- Mock handlers are keyed by command name and read args by the same camelCase keys (e.g. `collectionId`, `profileName`, `appId`, `sourcePath`). Any wrapper arg rename must update `src/lib/mocks/handlers/*` and the TS callers together.
- Mock error strings that deliberately mirror backend contracts: `metadata_unavailable:` prefix (mods.ts, togglable via `modsUnavailable`), `no_game_path:`, duplicate-name text. All other mock errors start with `[dev-mock]` (README rule in mocks/README.md).
- `wrapHandler.ts` classifies reads for `?errors=true`: `collection_get_defaults` and `collection_import_from_toml` are explicit reads; `list_*`, `fetch_*`, `check_*`, `preview_*`, `validate_*`, `*_export` match the heuristic. `scan_prefix_storage`, `cleanup_prefix_storage`, `get_prefix_storage_history` (starts with `get_` so a read) - `scan_` is not matched so `?errors=true` will reject it; unchanged by this work.
- Mock `check_version_status` emits `version-scan-complete`; real one doesn't. Mock `cleanup_prefix_storage` reports everything deleted (no allow-list) - consider adding a skip case for tests, optional.

## 5. Recommendations for the services/Tauri wrappers (UX-driven)

1. Keep Tauri command signatures byte-identical (names, arg names, `Result<T,String>`); wrappers only translate `AppError -> String` using existing `Display` text. Add a unit test in src-tauri (like `command_names_match_expected_ipc_contract` in export.rs/version.rs) when touching.
2.
