# YAN-847 / M1-35 technical research

Read-only source research. Paths below are relative to `src/crosshook-native/` unless prefixed `docs/`. Line numbers describe this worktree at research time. No application files changed and no build, test, lint, formatter, or smoke command was run.

## Executive findings

- There are **45 commands**, exactly: storage 3, mods 6, collections 13, launcher export 12, version 4, Steam 3, game metadata 4. All remain registered in `src-tauri/src/lib.rs`; names, top-level camelCase IPC argument keys, nested snake_case DTO fields, and result shapes must remain unchanged.
- Most domain work already exists in core. Move application orchestration, DTOs currently declared in commands, blocking-pool dispatch, metadata observation/auditing, profile resolution and error adaptation into app services; do not copy core scanners, serializers, image validation, script builders, or CRUD SQL.
- All 13 collections, 12 export, 4 version, Steam default/discovery, and 2 art-import commands are currently synchronous. `export_launchers` and `list_proton_installs` perform blocking filesystem work on their caller. The two async metadata/image commands also call synchronous SQLite/filesystem helpers internally: `async` alone is not an I/O isolation guarantee.
- Storage cleanup's fresh-scan allow-list is **application logic in Tauri**, not core (`commands/storage.rs:65-88`). It must move intact and become tested; checking only core cleanup loses this trust boundary. Today missing signatures are silently filtered rather than returned as skipped/error entries.
- `apply_collection_defaults` remains in `commands/profile/shared.rs:35`, intentionally deferred by ProfileWriter D7. `profile_load` calls it; summaries call the sibling resolver inside `ProfileWriter::list_summaries`' closure. Migrating just `collections.rs` leaves collection application logic in Tauri.
- Existing commands in all seven source files emit **no Tauri events and no AppEvent**. Metadata observations/audit rows are persistence, not events. Browser version mocks emit a completion event which the real single-profile version command does not.
- All 45 names have browser mock handlers. Four names have no production TS callsite found: `rename_launcher`, `find_orphaned_launchers`, `get_version_snapshot`, `import_custom_cover_art`; they are nevertheless registered public IPC and must remain.

## 2. Existing application-service conventions

### Construction and dependency wiring

- **Current** `Services::new(stores: &Stores, events: EventBus, runtime: tokio::runtime::Handle) -> Self` (`:71`), not the older two-argument signature in prior plan prose. Current bundle fields `:48-65`: settings, ui_settings, recent_files, diagnostics, health, profiles, background, launch. - `bootstrap/app_bootstrap.rs:116` constructs `Services::new(&stores, app.events().clone(), app.runtime_handle())`. `src-tauri/src/lib.rs:33-50` retrieves bundle and `.manage(services.<service>.clone())`; current raw stores remain managed for unmigrated modules.

### Errors

`error.rs:7-25` defines `AppErrorKind::{Validation {field: &'static str}, NotFound, Conflict, Unavailable, Io, Cancelled, Internal}`. `AppError` carries private sanitized message, `kind()` and `message()`; `AppError::validation(field,message)` is public and `new(kind,message)` crate-private (`:31-65`). It is not a new serialized envelope. Tauri keeps string errors.

Existing conversions: JoinError → Cancelled or Internal fixed message (`:68-77`); io → Io with kind only (`:79-83`); ProfileStore validation/not-found/conflict/I/O/TOML categories (`:85-122`); SettingsStore (`:149-164`); MetadataStore (`:206-240`) maps disabled/read-only/newer schema to Unavailable, validation/symlink to Validation(metadata), corruption/database to Internal, I/O to Io. There are **not** conversions in this file for CollectionExchangeError, LauncherStoreError, launcher export errors, mod detection errors, or the String-returning storage/image functions; migration needs local explicit sanitized mapping or narrowly added From impls. Do not map all failures to Internal, or lose the mods IPC prefix contract when adopting sanitized AppError.

### Events and jobs

- `events.rs:60-85` currently has only Resync, StartupJobFinished, ProfilesChanged, UiSettingsPersistFailed. There is no generic collection/storage/launcher-modified event to reuse. Do not invent emissions as if they existed before.
- `EventBus::publish(&self,event:AppEvent)->usize` (`:113-116`) never blocks; no subscribers is 0 not error. Lag is converted to `AppEvent::Resync` (`:143-148`). ProfileWriter publishes after persistence/effects **inside** the blocking closure (`profiles/writer.rs:56-86`) so dropping caller future cannot lose a write's event.
- `App::jobs(&self)->&JobRegistry` is at `app.rs:118`. `JobRegistry::start<F,Fut,R>(&self,spec:JobSpec,job:F)->Result<JobHandle,AppError>` (`jobs/registry.rs:134-195`); closure takes JobContext, Future is Send+'static, result is `Into<Outcome>`. `JobSpec::new(kind).with_key(JobKey)` supports exclusivity (`jobs/types.rs:60-81`). ## 6. Migration constraints and test implications

1. **Service ownership:** move 45 command bodies' orchestration into the six scoped services (Steam service also owns metadata/art), plus `profile/shared.rs` composition and its load/summary integration. Keep State extraction/IPC DTO filtering in shell only where presentation-specific; app DTOs must be toolkit-independent and usable by native UI.
2. **Fresh-scan cleanup is non-negotiable:** current app allow-list is exact tuple, fresh inventory comes from same P handle, duplicate targets filtered. Core cleanup rechecks references, managed marker, drive_c and canonical containment (`storage/prefix_health/cleanup.rs:36-194`), but does not itself perform a fresh global scan. Required tests need the service-level acceptance check as well as filesystem validation.
3. **Symlink regression gap (both kinds):** core checks `symlink_metadata(staged_root)` :118, not target; then canonicalizes target :156 and removes canonical file/dir :175-180. A stale target replaced by a symlink into the staged root is not rejected merely by containment. Orphan cleanup also lacks a no-follow target check: it recomputes `resolved_prefix_key` from the supplied path at :41, so both target/resolved strings can resolve to a substituted referent and satisfy equality at :83. The issue explicitly requires rejecting targets that became symlinks; preserve fresh-scan tuple membership and validate no-follow target/intermediate paths under approved roots in the owning implementation. String membership alone is insufficient to establish post-scan identity. Coordinate injectable roots and deterministic scan/delete barrier tests with the security report.
4. **Audits:** shell currently writes accepted core deleted/skipped rows and summary fail-soft (`storage.rs:91-139`). Invalid unallowlisted requests are not core skipped rows, so today they have no audit row. Tests must assert accepted-target rows and reclaimed summary without accidentally requiring all user-supplied arbitrary paths to be acted on.
5. **Golden bytes:** existing export tests assert substrings/permissions (`core/export/launcher/tests/export_write.rs:10-102`), previews assert headers/substrings (`tests/preview.rs:8-53`). These are not byte-identical golden tests. Freeze pre-move script and desktop bytes (including punctuation, quoting, LF behavior, optional configs, Steam/proton_run and loading modes) and assert app exports reuse core builders. Preview headers are separate expected outputs. Never regenerate expected output from the new service during comparison.
6. **Nonblocking:** move list_proton_installs/export_launchers and other filesystem/SQLite work through app run_blocking; awaiting an async method with inline sync core work is not sufficient. Network calls should remain async rather than blocking an executor or nesting a runtime. Metadata/image core currently intertwines sync cache reads/writes with HTTP; isolate those phases deliberately while reusing cache semantics.
7. **Errors/degraded mode:** app must explicitly gate SQLite-required collection/mod operations with Unavailable before writes; preserve classic availability DTO/error-prefix expectations in adapters. A read-time collection launch fallback remains fail-open except corruption. Launcher metadata observation/storage audits remain advisory. Do not change bare Vec/String classic returns into envelopes to expose a typed app error.
8. **Persistence classification:** no schema migration. SQLite remains collection rows/members/defaults JSON, mods, launcher observations, version snapshots, storage snapshot/audit history and image/metadata cache rows. Collection export TOML stays unchanged; profile TOML unchanged. Image files stay `$LOCALDATA/crosshook/cache/images` (`game_images/client/cache.rs:42-51`), imported art stays `$LOCALDATA/crosshook/media/{covers,portraits,backgrounds}` (`game_images/import.rs:11-15,33-65`). Scans/job result/progress/cancellation/exclusivity are runtime-only. Offline cached art remains visible; do not move cache into config/SQLite blobs or require online fetch to display a stored local path.
9. **Size/architecture rules:** root `CLAUDE.md:30-36,48-52` mandates core host gateway, thin shell, unchanged persistence classification and roughly 500-line cohesive files. Export orchestration is already 576 lines including tests; split service implementation/tests by cohesive responsibility rather than copying into a monolith.
