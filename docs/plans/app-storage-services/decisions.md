# YAN-847 orchestrator decisions

Binding for the plan and implementation of M1-35 (move storage, mods, collections, launcher export, version and Steam services into `crosshook-app`). Each decision favours security, data integrity, UX and stability. Paths are relative to `src/crosshook-native/`.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Why                                                                                                                                                                                                               |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Six service directories under `crates/crosshook-app/src/services/`: `storage/`, `mods/`, `collections/`, `launcher_export/`, `version/`, `steam/`. `game_metadata` commands fold into `steam/`. Each follows the profiles/launch shape: a `#[derive(Clone)]` struct, positional `new()`, `async` public methods, one `run_blocking` closure per operation, `AppError` only, `tests/` subdirectory, every file under ~500 lines.                                                                                                                                                                                                                                            | Matches the issue scope and the conventions of #533 and #535.                                                                                                                                                     |
| D2  | **Wiring.** `Services::new(&Stores, EventBus, Handle, JobRegistry)` gains the app's job registry (`App::jobs().clone()`); `App` already exists before `Services` in `app_bootstrap.rs`. Six new `Services` fields; six `.manage()` lines in `src-tauri/src/lib.rs`.                                                                                                                                                                                                                                                                                                                                                                                                        | Scan jobs are cancelled on app shutdown through the registry's parent token. No `JobRegistry::default()` ambient fallback.                                                                                        |
| D3  | **Scan as a job.** `StorageService::start_scan() -> Result<JobHandle, AppError>` runs the scan inside `JobRegistry::start` with the exclusive `JobKey` `prefix-storage-scan` (a concurrent request gets `Conflict`) and reports progress through `JobContext`. Because `Outcome` carries no payload, the result goes into a service-owned slot keyed by `JobId`, read with `scan_result(&JobId)`. `StorageService::scan()` is the awaitable convenience: start, wait for `Finished`, take the result. The Tauri command `scan_prefix_storage` awaits `scan()`, so its IPC result is unchanged.                                                                             | Satisfies "scan as a job" without changing the Classic contract; exclusivity prevents duplicate heavy scans.                                                                                                      |
| D4  | **Cleanup authorization.** `StorageService::cleanup(targets)` is the single orchestrator. In one blocking closure it: reloads profile references; runs a fresh scan; accepts only exact `(kind, resolved_prefix_path, target_path)` tuples from that scan, deduplicated; and passes the **server-produced** target onward, never the caller's object. Trusted roots come from profile inventory, never from the request.                                                                                                                                                                                                                                                   | Preserves today's allow-list (`commands/storage.rs:64-86`) and makes it the tested boundary.                                                                                                                      |
| D5  | **No-follow and containment hardening in core** (`crosshook-core/src/storage/prefix_health/cleanup.rs`). Before canonicalizing, `symlink_metadata` checks the target and the fixed intermediate components below the prefix (`drive_c`, `drive_c/CrossHook`, `StagedTrainers`). Symlinks, dangling links and non-directories are rejected. A staged target must be an immediate child of the staged root. Orphan and staged targets must be strict descendants of their roots, never equal to them. Canonicalization failure fails closed. Rejections become `skipped` entries with a fixed reason.                                                                        | AC1 ("rejects a target that became a symlink after the scan"). Placed in core so every caller benefits. A residual ancestor-swap race between check and delete is documented, not claimed fixed (see follow-ups). |
| D6  | **Rejected requests are reported.** Today a tuple missing from the fresh scan is dropped silently. It now appears in the existing `skipped` list with the reason `not present in a fresh storage scan` and gets a `skipped` audit row. Accepted deletions keep their per-target `deleted` audit row plus the `summary` row. Audit writes stay fail-soft after deletion. The `PrefixCleanupResult` shape is unchanged.                                                                                                                                                                                                                                                      | Honest UX and a complete audit trail with no IPC break.                                                                                                                                                           |
| D7  | **Metadata unavailable.** Collections writes and reads, mods add/update/remove/analyze, and version `set_trainer_version`/`acknowledge_version_change` check `MetadataStore::is_available()` first and return `AppErrorKind::Unavailable` before any write. `list_profile_mods` keeps returning `{available:false, mods:[]}`. Mods `detect` keeps working without the DB. Storage history keeps `available:false` with empty lists, and scan/cleanup keep working without the DB. The mods Tauri adapter maps `Unavailable` to the exact legacy string `metadata_unavailable: the metadata database could not be opened`, and keeps the `no_game_path:` prefix for detect. | Today collections silently no-op (create returns `""`). The issue requires `Unavailable` with no partial writes, and `useProfileMods.ts` parses those prefixes.                                                   |
| D8  | **Error text.** A crate-private helper maps `MetadataStoreError::Validation(msg)` raised by the collections and mods stores to `AppErrorKind::Validation { field: "collection" \| "mod" }`, keeping `msg`. `msg` is built from user-entered names, contains no paths, and is still passed through `sanitize_message`. All other variants use the existing `From<MetadataStoreError>`.                                                                                                                                                                                                                                                                                      | Keeps user-visible messages such as "a mod named … is already registered" and "collection not found".                                                                                                             |
| D9  | **`apply_collection_defaults` moves** from `src-tauri/src/commands/profile/shared.rs` to `CollectionsService::apply_defaults(profile, collection_id)`, with a pure, store-free core `resolve` helper for unit tests. The Tauri `profile_load` and the lifecycle callers delegate to it. The merge tests in `commands/profile/tests/optimizations.rs:66-193` move over, and the missing rows are added: `network_isolation`, `trainer_gamescope`, `mangohud`, `optimizations`, non-Validation fail-open, NULL defaults, disabled store. Policy unchanged: a blank id is identity, `Corrupt` bubbles, other errors fail open to the raw profile.                             | AC2; it is a reusable entry point for the native new-profile flow.                                                                                                                                                |
| D10 | **Launcher goldens** are captured from the **unmodified** code before any move. Fixed `$HOME`, no icon, fixed profile fixture; script and `.desktop` bytes go under `crates/crosshook-app/tests/fixtures/launcher_export/`. `tests/launcher_export_golden.rs` (`harness = false` if `HOME` must be set before the runtime starts) compares them byte for byte. Fixtures are never regenerated to make a test pass.                                                                                                                                                                                                                                                         | AC3.                                                                                                                                                                                                              |
| D11 | **Non-blocking.** Every moved Tauri command becomes `async` and delegates to a service method that does its blocking work inside `run_blocking`. That covers `list_proton_installs`, `export_launchers`, `default_steam_client_install_path`, the collections, version and export commands, and the custom-art imports. The Proton scan is not cached, because `reloadProtonInstalls` needs fresh results. `export_launchers` resolves only after the files are written and the metadata observe finishes.                                                                                                                                                                 | AC4; frontend callers already await promises.                                                                                                                                                                     |
| D12 | **IPC contract frozen.** Command names, camelCase argument keys, serde field names and return shapes stay byte-identical, including the four commands that have only mock callers. `fetch_game_cover_art` keeps `Option<String>`: the service returns `Unavailable` on network failure, cached art is still returned, and the adapter maps `Unavailable` to `Ok(None)`. No new events. The `check-mock-coverage.sh` and `command_names_match_expected_ipc_contract` checks must pass.                                                                                                                                                                                      | AC5 smoke tests and the Classic UI keep working unchanged.                                                                                                                                                        |
| D13 | **DTO placement.** A response type the CLI or native UI will need (scan/cleanup results, storage history, launcher info, version check result, collection export preview) lives in the service with its serde names unchanged. Purely Tauri-shaped wrappers stay in the adapter.                                                                                                                                                                                                                                                                                                                                                                                           | Reuse by the native UI without an IPC change.                                                                                                                                                                     |
| D14 | **Security hardening limited to moved code.** `rename_launcher` validates and sanitizes the **old** slug the same way delete-by-slug does, and requires the old and new paths to stay inside the launcher directories. Custom-art import keeps its magic-byte and 5 MiB checks and adds a bounded read: it stops reading once the limit is passed.                                                                                                                                                                                                                                                                                                                         | Closes path-containment gaps in code being moved without widening scope.                                                                                                                                          |
| D15 | **Preserved as-is, filed as follow-ups:** `rename_launcher` resetting the umu/runtime fields; the settings-failure inconsistency (hard error in `check_launcher_for_profile`, soft fallback in stale/slug matching); the duplicated appmanifest lookup outside `version/`; SteamGridDB initial-URL host/scheme validation in core; handle-pinned (openat/beneath) deletion for the ancestor-swap race; consulting `offline_mode` for art fetch; and the manual prefix storage cleanup test from the issue's test plan.                                                                                                                                                     | Behaviour-preserving refactor; the issue does not ask for these changes.                                                                                                                                          |
| D16 | Collections TOML import stays a non-mutating preview; the frontend still orchestrates the apply step. Mods add/remove stay metadata-only and never touch the filesystem.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | "Collections TOML export/import is unchanged"; no new mutation surface.                                                                                                                                           |

## Status / observable deltas

D1–D16 landed. Beyond the frozen IPC contract (D12), review surfaced these
observable behaviour deltas, all accepted as intended:

- **Concurrent scan (D3):** a concurrent `scan_prefix_storage` gets `Conflict`,
  and `scan()` waits at most 300 s. On timeout the blocking scan is **not**
  stopped (`spawn_blocking` cannot be cancelled): it keeps running and holds
  the `prefix-storage-scan` key until it finishes, so a scan started in that
  window also gets `Conflict`. The result slot is keyed by `JobId` and taken
  exactly once by `scan_result`.
- **D6 skipped entries:** a request tuple missing from the fresh scan (wrong
  kind, changed prefix or target path) is no longer dropped silently — it
  appears in `skipped` with the fixed reason `not present in a fresh storage
scan` and gets a `skipped` audit row.
- **D7 `Unavailable` scope:** collections `list` and `collections_for_profile`
  keep returning an **empty list** on a disabled metadata store (no startup
  error banner), while `list_profiles` and `get_defaults` return `Unavailable`.
  Collection and version **writes** return `Unavailable` before any write.
- **Error text (D8, extends the profile-writer D11 policy):** non-Validation
  metadata and profile/store errors surfaced by the moved commands now use the
  sanitized fixed `AppError` texts (e.g. `metadata database operation failed`,
  `profile file is not valid TOML`) instead of the raw store `Display`, and
  paths are home-redacted. Existing project policy, same as profile-writer D11;
  user-entered Validation messages are kept verbatim.
- **Staged cleanup authorization:** staged-trainer cleanup is now
  inventory-authorized — a `compatdata/<id>/pfx` entry discovered outside the
  trusted roots cannot be authorized by the fresh scan alone (D4/D5 boundary
  extended to the staged root).
