# YAN-835 orchestrator decisions

These decisions are binding for the plan and implementation of M1-34: moving the community, Lutris, discovery and ProtonDB services into `crosshook-app`. Paths are relative to `src/crosshook-native/`. Research lives in `research-*.md` in this directory.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Why                                                                                                                                                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Four service directories go under `crates/crosshook-app/src/services/`: `community/`, `lutris/`, `discovery/` and `protondb/`. Each follows the storage/onboarding shape: a `#[derive(Clone)]` struct, a positional `new()`, `async` public methods, `run_blocking` for store or filesystem work, `AppError` only, a `tests/` subdirectory, and files under ~500 lines. `Services::new` builds one `ProfileWriter` and clones it into `profiles`, `community` and `lutris`. Four `.manage()` lines go in `src-tauri/src/lib.rs`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Matches #540 and #542. A single writer keeps one lock and event path.                                                                                                                                                                                    |
| D2  | **IPC contract frozen.** All 19 command names stay the same. Argument keys keep their mixed spellings (`profile_name`/`output_path`, `source_id`, `appId`/`profileName`/`forceRefresh`/`suggestionKey`, `profileName`/`trainerGameVersion`). Serde shapes and return types stay byte-identical. `#[tauri::command]` fns stay in `src-tauri` as thin `async` delegates taking `State<Service>` and mapping `error.message().to_string()`. `protondb_accept_suggestion` stays on `ProfileWriter`. Mocks stay unchanged except where D7 changes behaviour. `check-mock-coverage.sh` and the command pin tests must pass, and ProtonDB gets a pin test.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | AC4. The Classic UI and smoke tests keep working.                                                                                                                                                                                                        |
| D3  | **Containment primitive in core.** `crosshook_core::fs_util::ensure_within_workspace(root: &Path, candidate: &Path) -> Result<PathBuf, WorkspacePathError>` has the variants `InvalidRoot`, `Traversal`, `OutsideWorkspace`, `NotFound` and `Io`. No raw paths appear in `Display`. It follows the research-security §2 semantics: (1) canonicalize the root once; (2) reject any `Component::ParentDir` in the original candidate, even if the path ends up inside; (3) resolve a relative candidate from the canonical root, never from CWD; an absolute candidate must component-prefix the supplied or canonical root spelling; (4) canonicalize the existing target and require `Path::starts_with(canonical_root)` with component-wise `OsStr` byte comparison; (5) reject dangling final symlinks; accept a final or intermediate symlink only if its resolved target stays inside; (6) no case folding and no Unicode normalization. Return the resolved path, which callers then read. This helper does not support missing candidates (`NotFound`), because no caller needs it to.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | AC1. Core placement lets the indexer and the Lutris scanner share it, since core cannot depend on app. Byte-exact comparison is the safe reading of "case and Unicode tricks" on case-sensitive ext4. Normalizing could authorize a different directory. |
| D4  | **Where containment applies.** (a) `CommunityService::import_profile`, the mutating import, requires the candidate to be inside **some** resolved subscribed-tap workspace. It passes the resolved path to `ProfileWriter::import_community` and also requires a regular `.json` file. (b) `prepare_import` is a read-only preview of a file the **user picked** in a dialog, and its result is saved later through `profile_save`. It keeps accepting any local regular `.json` file (no behaviour change), but it now reads the **canonical** path and runs the same `ensure_within_workspace` classification. That gives one code path, and the result is logged at debug level. (c) The community indexer (`core/community/index.rs`) skips symlink entries for both directories and files through `DirEntry::file_type()`, which does not follow links, so it never reads outside a tap. (d) The Lutris scanner checks each `games/*.yml` candidate and `pga.db` with `ensure_within_workspace(lutris_root, …)` and skips (with a diagnostic) anything that escapes the root.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Enforcing containment on preview would break the Browse "import from file" flow, which is a UX regression. That flow writes nothing and needs explicit user selection. Every path that reads tap content for import or indexing is now contained.        |
| D5  | **Tap add and remove.** `add_tap` runs `normalize_subscription` before persisting. Invalid URLs, branches or pins become `Validation` errors and nothing is written; pins are checked with `is_valid_git_sha`. Dedupe runs on the **normalized** `(url, branch, pinned_commit)` triple. `remove_tap(tap)` is service-only and adds no Classic IPC command; it removes by normalized identity and leaves clones and SQLite rows alone, as the frontend does today. Settings writes use `SettingsStore::update`, which preserves extras; returned taps have `extra` cleared.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | This is a strict tightening for data integrity. The shipped UI already sends normalized taps.                                                                                                                                                            |
| D6  | **Sync as a cancellable job with real process cancellation.** The core tap-sync flow (`clone` → `fetch`/`reset`/`clean` or pinned checkout → `rev-parse` → index) gets an **async** variant. It takes an injected git runner, `trait TapGitRunner { async fn run(&self, inv: GitInvocation) -> Result<GitOutput, GitRunError> }` (async-trait, or a boxed future if async-trait isn't already a dependency), where `GitRunError` distinguishes `Cancelled` from `Failed`. Core keeps argv and env policy, validation and result construction. The existing sync `sync_many` either goes away, if it has no other callers, or becomes a wrapper over the shared step builder. The app runner builds each git child with `platform::host_command_with_env_and_directory_lifecycle("git", env, dir, {})` and `process_group(0)`, drains stdout/stderr (bounded), and waits through `jobs::supervise_child(child, ctx.cancel_token(), DEFAULT_KILL_GRACE)`. `CommunityService::start_sync() -> Result<JobHandle, AppError>` runs the pipeline inside `JobRegistry::start` with the **non-exclusive** spec `community-sync`. A service-held `tokio::sync::Mutex` serializes overlapping syncs (they queue rather than `Conflict`). The registry's cancel token is checked before every git step and before indexing. **Cancelled never becomes `CachedFallback`**, and after cancellation no index, offline upsert or backfill runs. The result goes into a slot keyed by `JobId` (storage D3 pattern). `sync()` is the awaitable convenience that the Tauri `community_sync` awaits, so the IPC result is unchanged. Clone gets an explicit `--` before the URL. | AC2. `run_job` would leave git running after cancellation (research-security §3). Under Flatpak, the lifecycle gateway is required to kill the host process. The non-exclusive key avoids spurious `Conflict` (memory and #542 D2).                      |
| D7  | **Offline behaviour.** If `settings.offline_mode` is on, `sync` returns `AppErrorKind::Unavailable` ("offline mode is enabled") before any git run. External search in offline mode serves fresh **or** stale cache only and makes no live fetch. When nothing is cached it returns `Unavailable`. The catalog, both indexed lists, ProtonDB lookup and suggestions are **not** gated and keep their existing `degraded`/`from_cache`/`is_stale`/`Stale` markers. The mock handlers for `community_sync` and `discovery_search_external` mirror the offline gate only if the mocks model `offline_mode`; otherwise they stay unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Spec, "Persistence & usability". Hiding stale cached search results would degrade offline UX, so `Unavailable` only applies when there is nothing to show.                                                                                               |
| D8  | **Sync orchestration is preserved.** The order is: index → offline upsert → `last_sync_at` read-back, warning-only, with the metadata store possibly disabled. The first per-tap hard error still aborts with `Err`, same as today. `from_cache` keeps the previous `last_sync_at`. v25 `trainer_loading_mode` is populated by the re-index after the watermark reset. A test pins it: index with an old watermark of NULL, then assert the column is set.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | AC3, and a behaviour-preserving move.                                                                                                                                                                                                                    |
| D9  | **Error text.** New `From`/mapper impls for `CommunityTapError`, `LutrisImportError` and `WorkspacePathError` map to `AppError` with no paths, git stderr or SQL: traversal and outside map to `Validation { field: "path" }` with a message like "community profile path is not inside a known tap workspace"; missing maps to `NotFound`; git failure maps to `Io` "failed to sync community tap"; cancelled maps to `Cancelled`. User-entered validation texts are kept verbatim (tap URL/branch/pin, the external-source validator, `unknown profile: {name}`, the duplicate and missing source id texts, and the ProtonDB dismiss texts).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Existing sanitized-error policy (profile-writer D11 and storage D8).                                                                                                                                                                                     |
| D10 | **Discovery and ProtonDB move as they are.** External search keeps the 1 h TTL, the cache key and the concurrency/size constants. ProtonDB keeps the 6 h TTL and its stale fallback. Dismiss keeps 30-day retention and its texts and adds no eviction side effect. The catalog keeps the degraded fallback on any DB error. Everything becomes async off the caller thread.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | The issue's scope is a move.                                                                                                                                                                                                                             |
| D11 | **Preserved as they are, filed as follow-ups:** private-host and redirect policy plus streamed byte limits for discovery and ProtonDB fetches; strict numeric ProtonDB app ids; revalidating external sources at fetch time; workspace slug collisions; git env stripping and hooksPath; `openat2` pinned-handle reads (the race boundary); a Classic UI cancel button for sync (there is no generic job-cancel IPC); and the manual Community/Discover/Compatibility checks from the test plan.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Not required by the ACs. Each is a separate security or UX decision.                                                                                                                                                                                     |
| D12 | **Tests (critical only).** Core: the `ensure_within_workspace` matrix with real temp dirs (nested accept, `..` relative and absolute, absolute outside, `root-evil` sibling prefix, outward intermediate and final symlinks, dangling symlink, in-root symlink accepted, case-sibling and NFC/NFD-sibling dirs that contain real JSON rejected), plus an indexer test that skips symlinks. App: tap dedupe on the normalized triple and invalid tap rejection; sync against a **local bare git repo fixture**, which covers index, offline upsert, `last_sync_at` backfill, `trainer_loading_mode`, and `from_cache` keeping the old timestamp; non-blocking sync shown with a gated fake runner; cancellation, where a fake or `sleep`-based runner proves the child is killed, the result is `Cancelled` and no index row is written; offline gating for sync and search; import containment for prepare (accept outside) and import (reject outside, accept nested). Smoke: `npm run test:smoke`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | ACs plus the test plan.                                                                                                                                                                                                                                  |
