# YAN-794 (M1-39) — `crosshook-view-model` decisions

Binding for the plan and implementation. Evidence lives in `research-technical.md`, `research-parity.md` and `research-practices.md` next to this file.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | The crate has **no default dependencies**. It owns small input types (`ServiceError`/`ServiceErrorKind`, `ProfileCard`, `SessionKind`, `SessionEvent`, and an opaque `SessionId(String)` built from core's `SessionId` `Display` under the `app` feature) instead of depending on `crosshook-core`/`crosshook-app`.                                                                                                                                                                                                                                     | Both crates depend on tokio unconditionally (core directly and via reqwest/zbus; app directly), so depending on them makes the AC "no tokio in `cargo tree -p crosshook-view-model`" impossible. Extracting a tokio-free types crate is far larger than this 3-pt issue (`AppError` has 12 `From` impls, one for a tokio type, and its constructor reads `$HOME`). |
| D2  | An optional **`app` feature** (off by default) adds `crosshook-app` + `crosshook-core` and the conversions: `From<&AppError> for ServiceError` (exhaustive `match`, no `_` arm, as a drift guard), `From<&ProfileSummary>` into `ProfileCard` (favorite supplied separately), `RunningSessions` → snapshot, and `fn session_event(&AppEvent) -> Option<SessionEvent>` (a function, because `AppEvent` is `#[non_exhaustive]`). No self dev-dependency with features (that would put tokio back in the plain tree).                                      | Satisfies the issue's "depends on core model types and app DTOs/`AppError`" without breaking the tokio AC. The orphan rule means the conversions must live in this crate, not in each toolkit bridge.                                                                                                                                                              |
| D3  | Crate-local `clippy.toml` lists **concrete items** only (std::fs functions and `File`/`OpenOptions`, `std::process::{Command, Child, exit}`, `std::thread::{sleep, spawn}`, `std::env::{var, var_os}`, `SystemTime::now`/`Instant::now`, `std::net::TcpStream`, and tokio items for intent).                                                                                                                                                                                                                                                            | Module paths and globs (`std::fs`, `tokio::*`) are silently ignored by clippy 1.95 and `-D warnings` still passes. tokio entries are inert while tokio is absent; the real tokio guard is D4.                                                                                                                                                                      |
| D4  | Generalize `scripts/check-app-deps.sh` into a per-package table: `crosshook-app` (normal edges, toolkit ban, unchanged) and `crosshook-view-model` (default edges normal+build+dev, toolkit + `tokio*`/`mio` ban). Extend `--selftest`. Wire `--selftest` and the check into the `rust` job in `.github/workflows/lint.yml`, plus a view-model `--all-features` clippy and test step.                                                                                                                                                                   | The script exists but no workflow runs it. One script, not a copy (DRY). Workspace clippy builds default features only, so the `app` feature code would otherwise never be linted or tested.                                                                                                                                                                       |
| D5  | `lib.rs`: `#![forbid(unsafe_code)]`, `#![deny(missing_docs)]`, `#![deny(clippy::print_stdout, clippy::print_stderr, clippy::dbg_macro)]`. No `tracing`/`log` dependency.                                                                                                                                                                                                                                                                                                                                                                                | `[lints.rust]` next to `[lints] workspace = true` is a manifest error, so the forbid goes in source. No I/O, env, clock or logging in a pure crate.                                                                                                                                                                                                                |
| D6  | `Cargo.toml`: `version.workspace = true`, edition 2021, `[lints] workspace = true`, added to workspace `members`. **Not** added to `scripts/prepare-release.sh` or the `release.yml` version check.                                                                                                                                                                                                                                                                                                                                                     | Both grep for a literal `version = "X"` line; an inherited version would fail release prep. The workspace version bump already covers the crate. Deviates from §11.1 of the migration research on purpose.                                                                                                                                                         |
| D7  | `ViewModel` trait exactly as the issue states, with no extra bounds. Service results return as intents. Effects are plain `Debug + Clone + PartialEq + Eq` data.                                                                                                                                                                                                                                                                                                                                                                                        | Maps 1:1 onto iced `update`→`Task::batch` and gpui `entity.update` + `cx.spawn`.                                                                                                                                                                                                                                                                                   |
| D8  | `Form<T: FormModel>`: per-form `Field` enum; `FormModel::field_id(Field) -> &'static str` is the only place the backend id appears. Dirty is **derived** (`value` vs `baseline` per field); touched is stored. Field errors in a `BTreeMap`.                                                                                                                                                                                                                                                                                                            | Type-checked fields; no stored dirty flag to desync; deterministic order for asserts.                                                                                                                                                                                                                                                                              |
| D9  | Submit FSM `Idle → Submitting(SubmitId) → Succeeded \| Failed`. A submit while submitting returns `None` (no second save). Results with a stale id are ignored. Success sets `baseline` to the **submitted snapshot**. A client-invalid submit returns `None`, goes to `Failed`, sets field errors and touches every field. Edit after Succeeded/Failed returns to `Idle`, clears the form error and only the edited field's error.                                                                                                                     | Mirrors the SteamGridDB section's saving/error/saved states and `useRunExecutable`'s per-field error clearing; prevents double saves and lost edits.                                                                                                                                                                                                               |
| D10 | Error mapping: `Validation{field}` with a known field → field error; unknown field (e.g. `"settings"`) and `NotFound/Conflict/Unavailable/Io/Internal` → form-level error with the message verbatim (already sanitized), clearing previous field errors; `Cancelled` → `Idle`, no banner. The crate never calls `sanitize_message`. Client validation messages are `&'static str`.                                                                                                                                                                      | Never swallow errors (CLAUDE.md); cancellation is a shutdown race, not a user error; `sanitize_message` reads `$HOME`.                                                                                                                                                                                                                                             |
| D11 | Library example parity with React (`LibraryPage.tsx:124-145`, `useLibraryProfiles.ts`): search → filter → sort. Search trims and lowercases, substring on `name` or `game_name`; empty passes all. Filters: `All`, `Favorites`, `Installed` (`steam_app_id` non-empty and not `"0"`), `CurrentlyRunning` (exact name in running set). Sorts: `Recent` (source order) and `Name`. **Dead TS keys (`recentlyLaunched`, `lastPlayed`, `playtime`) are not ported.**                                                                                        | Only the keys the toolbar exposes do anything today; "no dead code".                                                                                                                                                                                                                                                                                               |
| D12 | `Name` sort comparator: key = `game_name` if non-empty else `name`; compare `key.to_lowercase()`, then case-swapped bytes (lowercase first), then `name` (unique, so the order is total). Known divergences from ICU `localeCompare` (punctuation vs digits, accented letters after `z`) are documented in rustdoc and not asserted. Search trim uses `str::trim`; the U+FEFF/U+0085 difference is documented.                                                                                                                                          | Deterministic, no ICU dependency; total order makes input-order-independence a valid property.                                                                                                                                                                                                                                                                     |
| D13 | Currently Playing count = number of **distinct** `Some(profile_name)` over live `Game` sessions (trainer and anonymous excluded). Not intersected with loaded summaries (React parity); the `CurrentlyRunning` filtered list is ⊆ summaries. Session tracker follows the seq contract: events before the first snapshot are buffered; a snapshot replaces state and applies buffered events with `seq > snapshot.seq`; events with `seq <= baseline` are ignored; duplicate start and unknown exit are no-ops; `Resync` emits `RequestRunningSessions`. | Matches `runningSessionsStore.ts` and the `sessions.rs` seq contract from M1-42.                                                                                                                                                                                                                                                                                   |
| D14 | Visible indices are cached and recomputed inside `reduce` on state change, using a lowercase search key precomputed once per card on load. Selectors read the cache.                                                                                                                                                                                                                                                                                                                                                                                    | View functions may run every frame; no per-frame allocation.                                                                                                                                                                                                                                                                                                       |
| D15 | Settings form example fields: `profiles_directory` (text; trimmed; empty means default; receives the real backend `Validation { field: "profiles_directory" }`), `recent_files_limit` (numeric text; client check: integer in `1..=100`, fixed message), `log_filter` (select of `error\|warn\|info\|debug\|trace`). The submit effect carries the parsed values. The `1..=100` bound is a documented UI-input check, not a replacement for core's clamp (which still runs server-side).                                                                | Real backend field ids; one example each of server field error, client validation and select-dirty semantics.                                                                                                                                                                                                                                                      |
| D16 | `testing` module: `pub`, gated `#[cfg(any(test, feature = "testing"))]`. `Script::new(vm).step(intent, expected_effects).assert_state(f).into_inner()`, `#[track_caller]`, exact ordered effect comparison with step index in the panic. Fixture builders in `testing::fixtures`. proptest strategies stay in `#[cfg(test)]` files.                                                                                                                                                                                                                     | Reusable by `crosshook-ui` screen tests later; no extra dependencies.                                                                                                                                                                                                                                                                                              |
| D17 | `proptest` 1.x as a dev-dependency with `default-features = false, features = ["std"]`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | AC requires property tests; slim features drop `rusty-fork`/`tempfile` and keep the dev tree tokio-free.                                                                                                                                                                                                                                                           |
| D18 | Docs in the same PR: crate `README.md` (rules, contract, FSM and error tables, "Adding a view-model for a ported screen", testing, storage boundary = runtime-only, dependencies/`app` feature); one Architecture sentence in `CLAUDE.md`, `AGENTS.md` and `.ai/rules/project.md`; AGENTS.md Stack Overview row and Directory Map entry; `check-app-deps.sh` in the Commands lists.                                                                                                                                                                     | AC "public API documented, README section"; agent docs must know the new crate.                                                                                                                                                                                                                                                                                    |
| D19 | Not in scope: a generic store/dispatcher, derive macros, async/debounced validation, autosave/launch FSMs, wiring into any UI. Nothing user-reachable changes, so no feature switch is needed.                                                                                                                                                                                                                                                                                                                                                          | 3-pt scaffold; M2 issues port screens.                                                                                                                                                                                                                                                                                                                             |
