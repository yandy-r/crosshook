# YAN-855 (M1-36) — picked host path resolution: decisions

Linear: YAN-855 · GitHub: #564 · Target release: v0.7.0-alpha.1

Binding decisions for the implementation. Paths relative to `src/crosshook-native/`.

| D1  | Add `crosshook_core::platform::resolve_picked_host_path(path, &impl XattrReader, &impl DocumentsPortal) -> Result<PathBuf, HostPathError>` (async) plus a convenience `resolve_picked_host_path_default(path)` using the real xattr reader and zbus portal. New module `platform/picked_path.rs`.                                                                                                                                                                                                                                                | Spec. | D2  | Resolution order for host use: trim → empty is `HostPathError::Empty` → `/run/host` exact is `/` → `/run/host/…` is stripped → document-portal path (`/run/user/<digits>/doc/<doc_id>/<entry>[/rest]`): xattr first, then `org.freedesktop.portal.Documents.GetHostPaths([doc_id])` (version 5) with a 2 s timeout → anything else passes through. | D3  | A document-portal path that resolves neither way returns `HostPathError::UnresolvedDocumentPortalPath`; it is never returned as-is for host use. A single trailing NUL is stripped.                                                                                                                                                               | Spec: no silent sandbox paths. ## Persistence and usability

- **Data classification:** no new data and no schema change. Profile TOML string fields (game, trainer, Proton, prefix and working-directory paths) now get a real host path for new picks instead of a sandbox-only `/run/user/<uid>/doc/…` path.
- **Migration and backward compatibility:** none needed. Portal paths that are already saved still get the best-effort `normalize_flatpak_host_path` repair at use time.
- **Degraded behaviour:** if a host-use pick can't be resolved, an alert explains why and the pick is discarded (the previous value is kept). Sandbox-use picks never fail resolution.
- **User visibility:** the alert is the only new UI. There are no settings.
