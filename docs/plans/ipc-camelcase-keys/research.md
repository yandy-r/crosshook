# IPC top-level argument key audit (camelCase)

Scope: every `callCommand(` site in `src/crosshook-native/src` (excluding `__tests__`, `*.test.*`, `src/test/`), and every mock handler registered with `map.set('<cmd>', …)` under `src/lib/mocks/handlers`.

## Method

- Tauri macro version: `tauri-macros` 2.6.2 (`src/crosshook-native/Cargo.lock`). Its default `ArgumentCase::Camel` means top-level invoke keys are the Rust parameter names in lowerCamelCase.
- All 163 `#[tauri::command]` fns live under `src-tauri/src/commands/**`. None uses `rename_all`, and no parameter has a `#[...]` attribute. Injected params are excluded from "expected keys": `State<'_, …>`, `AppHandle`/`tauri::AppHandle`, `tauri::Webview`.
- `src/lib/ipc.ts:7-17`: `callCommand` passes `args` unchanged to `invoke` (`ipc.ts:10`) or to `runMockCommand` (`ipc.dev.ts`). There is no other `invoke(` call site, and no wrapper renames keys.
- I found 209 literal call sites covering 149 distinct commands. Every command name resolves to a Rust fn. `HeroProfileActionsBar.tsx:10` and `useProfileActions.ts:17` match `invoke` only inside comments (`'profile_save*'`), so they are not call sites.
- A `?` on an expected key means the Rust type is `Option<…>`, so the key is optional. Every key without `?` is required. No call site omits a required key.
- I compared each call site's object-literal keys to the expected keys (spreads expanded by hand). I also parsed each mock's destructuring and `args.x` reads, then checked helper-based mocks by hand.
