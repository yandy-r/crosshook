# YAN-798 launch service: decisions

Where the research files disagree, these decisions apply. Paths are relative to `src/crosshook-native/`.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | `ProcessSpawner` is a single method, `spawn(&mut tokio::process::Command) -> io::Result<tokio::process::Child>`. It receives the already-built core command. It does not use process groups, `supervise_child`, `killpg` or `kill_processes_using_prefix`. Plain `wait()` is kept.                                                                                                                                                                                                                                                                                                                           | Stability and security: no new kill paths. Today a cascade to a trainer without gamescope only records `LinkedSessionExit`, and the gamescope watchdog only kills its own `ShutdownTarget`. Process groups would kill non-gamescope trainers and stop Ctrl-C from reaching the game. Taking a built `Command` keeps all host tools behind the `platform` gateway (ADR-0001). (research-practices §3, research-security C-1/C-2) |
| D2  | Each session gets its own bounded `tokio::sync::broadcast<LaunchEvent>`, created before spawn. `LaunchEvent::{Log, Injection, Diagnostic, Exited}` each carry `session_id`. A lagged subscriber sees a dropped-lines notice. `Exited` is published exactly once, after every other event. Launch events stay off the global `AppEvent` bus.                                                                                                                                                                                                                                                                  | Session-scoped streams without changing the global bus contract; uses the same subscribe-before-start pattern as `JobRegistry`.                                                                                                                                                                                                                                                                                                 |
| D3  | Launches are not `JobRegistry` jobs. Streaming reuses `log_tail::follow`, which replaces the 500 ms whole-file re-read. A single capped tail reader replaces both copies of `safe_read_tail`.                                                                                                                                                                                                                                                                                                                                                                                                                | The job outcome types have no exit codes or diagnostics. `log_tail` already handles lossy UTF-8 and caps reads.                                                                                                                                                                                                                                                                                                                 |
| D4  | Wire payloads: `launch-log` becomes `{ line, session_id }`, one event per line. `normalizeLogMessage` already accepts `{ line }`. `launch-diagnostic` adds `session_id` in an emit-time wrapper, so the `DiagnosticReport` type and the persisted `diagnostic_json` don't change. `launch-complete` becomes `{ code, signal, session_id }`. `injection-log` is unchanged. Every event uses the same `SessionId::to_string()`. TypeScript types and browser-dev mocks are updated in the same PR.                                                                                                             | This is the issue's "optional `session_id`" requirement. A bare string has nowhere to carry an id. Sending one event per line keeps console timestamps and counts as they are. Nothing is emitted twice. (research-ux)                                                                                                                                                                                                          |
| D5  | Event order inside a session stays as today: log lines, the suppression summary, the diagnostic, complete, the trainer injection-log wrap-up, the cascade (game sessions only), post-exit hooks, deregister, portal unregister. The finalizer side effects (history row, version snapshot, known-good tag) keep their current conditions.                                                                                                                                                                                                                                                                    | Data integrity. No storage-format changes (issue's storage boundary).                                                                                                                                                                                                                                                                                                                                                           |
| D6  | The finalizer runs under a drop/panic guard, so a panic in the stream task still runs the cascade, post-exit hooks, deregistration and the `Exited` / `launch-complete` events. Pre-launch and post-exit hooks run through `run_blocking`.                                                                                                                                                                                                                                                                                                                                                                   | Stability. Today a panic skips teardown (research-security H-1), and hooks can block a runtime worker for up to 10 s.                                                                                                                                                                                                                                                                                                           |
| D7  | Pipe readers read bytes and decode them lossily, with partial lines capped at 64 KiB. They don't stop on invalid UTF-8.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Today `lines()` breaks on the first bad byte and can stall the child (research-security H-2).                                                                                                                                                                                                                                                                                                                                   |
| D8  | One pure predicate, `gamescope_required(req, kind, env)`, replaces the four Tauri copies. It decides whether the watchdog is spawned and whether a PID capture path is used. It must reproduce every row of the current truth table (research-business). Core's `should_skip_gamescope` stays. Three suspicious behaviours are kept as they are and filed as follow-ups: (1) Flatpak trainers never write the gamescope PID capture file; (2) the watchdog drops the cancel channel when the executable name is empty; (3) the hook environment for a Flatpak Steam trainer is built as Steam.               | Refactor without behaviour change; the fixes get their own reviewed issues.                                                                                                                                                                                                                                                                                                                                                     |
| D9  | The session registry moves into `Services`. The separate `.manage(Arc::new(LaunchSessionRegistry))` in `src-tauri/src/lib.rs` goes away; Tauri gets the registry from `Services`. The `#[tauri::command]` launch commands stay in `src-tauri` as thin async delegates with unchanged names, arguments and return types. `validate_launch`, `preview_launch`, `build_steam_launch_options_command`, `list_launch_history_for_profile`, `list_running_profiles` and `launch_reset_sessions` move into the service. `check_gamescope_session`, `launch_platform_status` and `check_game_running` stay in Tauri. | Follows the issue's scope. `check-mock-coverage.sh` scans `src-tauri` for command names.                                                                                                                                                                                                                                                                                                                                        |
| D10 | CLI, keeping YAN-798's scope separate from YAN-837's: `crosshook-cli launch` uses the service's tail/stream helpers and its shared tail reader. `stream_helper_log`, `drain_log` and `safe_read_tail` are deleted. The CLI does **not** call `start_game` and writes no launch history; both stay in YAN-837 (M1-09). Dry-run output, exit codes, log paths and `--scripts-dir` checks are unchanged. A golden test captured from the CLI before the change pins its output.                                                                                                                                 | Meets the issue's "uses this service and its tail" and "output unchanged" criteria without taking on M1-09's behaviour changes (history rows, hooks, `proton_run` output).                                                                                                                                                                                                                                                      |
| D11 | Trainer parity test: a Steam-profile trainer request and a `proton_run` trainer request produce the same env, `working_directory` and gamescope config from the builder, with UMU disabled in the fixture. Both the host and the Flatpak builder variants are checked. On the host, a Steam trainer runs through a shell script, so the comparison is between the effective builder inputs and outputs, not argv.                                                                                                                                                                                            | Follows the acceptance criterion and the research-business finding.                                                                                                                                                                                                                                                                                                                                                             |
| D12 | Not included, filed as follow-ups: `create_new` / symlink hardening for `/tmp` log and PID files (A-1); `crosshook-cli` in the `check-host-gateway.sh` scope (part of YAN-837); the CLI's existing bugs (B1 stale log replay, B2 `proton_run` captures no log, B3 gamescope hang, B4 `--config` misuse).                                                                                                                                                                                                                                                                                                     | Each one changes behaviour and needs its own review.                                                                                                                                                                                                                                                                                                                                                                            |
